philosophy

People don't read interfaces. They feel them.

Eight beliefs that guide everything I design. When I'm torn between two options, I come back here.

The detail is the product

Two apps with the same features don't feel the same. The difference lives in 200 milliseconds, in a 6-pixel blur, in a button that shrinks when you touch it.

That's where I spend most of my time.

Quiet frame, loud content

Neutral backgrounds and restrained chrome, so the content can be loud: photos, people, places, objects and color.

A quiet frame around an empty screen is just a grey screen.

Depth with light, not lines

I separate layers with blur, transparency and soft shadows. Borders and boxes divide; blur brings order without cutting the image.

A layered interface makes sense without explaining it.

Motion explains

I animate to show where something comes from and where it goes. The sheet rises from the bottom because it lives at the bottom; the check grows out of the button that asked for it.

If an animation doesn't answer a question, I cut it.

One color leads each story

Each project picks one lead hue and commits to it, from a sharp accent to whole surfaces. Its world brings a few softer companion tones, and photos, people and data bring their own color on top.

One color held steady gets remembered. Five lead colors get forgotten.

Light and dark from day one

I design both modes in parallel. I don't invert colors: each mode gets its own decisions for shadow, glass and contrast.

The mode belongs to whoever uses the app. It isn't mine.

Words are design too

Short copy, active voice, zero jargon. Names are written the way their owners write them, and flows get an arrow.

If a button needs explaining, the button is wrong.

Alive, not sterile

Every screen shows something from the real world: a photo, a face, a place, an object or data in color.

If a screen could belong to any app, it isn't finished.

Every decision has a reason. If I can't explain it, it's out.

how I design both modes
always
  • I design both modes in parallel, in the same file and the same week.
  • Every token has a value chosen per mode. Nothing gets inverted automatically.
  • In light I separate with shadow; in dark, with surface and light.
  • I check AA contrast in both before I call anything done.
  • By default I follow the system and let people choose: system, light or dark.
never
  • Mid grey as a dark background "so it's not so black".
  • Large dark shadows in dark mode.
  • One mode finished and the other "later".
  • The same glass in both modes: light needs more opacity.
  • Icons or illustrations that only work on one background.

motion

Fast in, soft landing. Three curves, seven durations, eight patterns.

The rules of motion at screen scale. Everything comes from the tokens in tokens.css.

Respond instantly

Every touch gets a visual response in under 100 ms. If the action takes time, the button changes state before the result arrives.

Enter fast, slow down soft

Almost everything uses ease-out. What opens takes 420 ms; what closes, 280 ms.

Nothing appears out of nowhere

Elements come in from where they start: the sheet from the bottom, the toast from the edge, the check from the button.

One thing at a time

Things that enter together get staggered: 120 ms between lines, 50 ms between items (6 max), 30 ms between words.

Text doesn't dance

Text reveals and then stays still. It never starts invisible, never bounces and never moves while someone reads it.

Weight sets the speed

Small things move in 120 to 240 ms, components in 420, stages and images in 800. The bigger it is, the further and slower it travels, never with a bounce.

curves
ease-out · defaultcubic-bezier(.22, 1, .36, 1)

Entrances, responses, reveals.

ease-in-out · travelcubic-bezier(.65, 0, .35, 1)

Something crossing the screen, morphs, closing.

spring · confirmcubic-bezier(.34, 1.56, .64, 1)

Small things only: check, chip, bounce on release.

what animates and what doesn't
yes
  • The response to every touch.
  • State changes: loading, sent, error.
  • New content that arrives after an action.
  • Transitions between screens and sheets.
  • Numbers that change value.
no
  • Text while it's being read.
  • Parallax or scroll that hijacks the page.
  • Infinite loops in UI, except loading and live states.
  • Bounces on large elements.
  • Load animations nobody asked for.
reduced motion

With prefers-reduced-motion or "Reduce Motion" on iOS: no movement, no scale and no blur. State changes become a 120 ms crossfade, numbers show the final value and loops stop. Haptics stay.

skills

My design, installed in your agent. One command with skills.sh.

Everything on this page also ships as agent skills through skills.sh. Once they're installed, the agent loads them on its own when the task calls for it: no prompt to paste, no links to share. They work with Claude Code, Cursor, Codex and any agent that supports the open Agent Skills format.

agustinoberg-designWhat my design is, exactly.For anything that must look, move and read like I designed it: screens, components, sites, decks and Dribbble shots. It ships the tokens for the web (CSS) and React Native, code for every signature pattern and a visual pre-flight.
agustinoberg-productHow to build a product well.For whole apps, sites and flows. It works like a design studio: a brief, research on real products, two or three directions built from your product, a critique and the delivery. Your brand leads; it adds my craft and a few signature touches, and my own look only if you ask. It loads agustinoberg-design.
install

Run it in your project's folder. The CLI asks which skills and which agents; the flags skip the questions. The repo is private for now, so installing needs access to it.

every skill, in this project
npx skills add AgustinOberg/agustinoberg
one skill, for Claude Code, no questions
npx skills add AgustinOberg/agustinoberg --skill agustinoberg-design -a claude-code -y
both skills, in every project
npx skills add AgustinOberg/agustinoberg --skill agustinoberg-design --skill agustinoberg-product -g

Then ask for the work as usual, like "build a travel app with my design guidelines". The skill does the rest.
